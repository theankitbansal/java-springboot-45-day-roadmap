# Java + Spring Boot: 45-Day Roadmap

A hands-on learning plan to strengthen Java fundamentals, build Spring Boot REST APIs, practise SQL and testing, and finish with a Loan Application Management API.

## Learning goals
- Build strong Java fundamentals and explain core concepts in interviews.
- Learn Spring, Spring Boot, REST, JPA/Hibernate, SQL, testing, security, and microservice basics.
- Build a portfolio project incrementally.
- Use knowledge checks to identify gaps instead of rushing through topics.

## Daily study routine
Suggested core session: **2 hours**, around **7:00 PM IST**.
1. **Learn — 30 minutes:** concepts and banking/loan-processing examples.
2. **Practise — 60 minutes:** write code, run it, and explain the result.
3. **Assess — 30 minutes:** conceptual questions, interview questions, and a small coding problem.
4. **Optional:** another 30 minutes for revision or project work.

## Assessment rule
A day is not complete just because the lesson was read. Answer the knowledge-check questions and explain your reasoning. We will review correctness, clarity, practical application, and misconceptions. If something is unclear, we will revisit it using a different explanation and real-world examples, then retest. **Only mark a day complete after you confirm that you are satisfied with your understanding.**

## Technology/version note
Core Java examples will stay compatible with **Java 8** unless a lesson explicitly compares newer versions. Spring Boot 3.x requires Java 17 or newer, so the capstone scaffold uses **Spring Boot 2.7.18 with Java 8** for compatibility and learning purposes. Spring Boot 2.7 is end-of-life; do not treat this legacy version as a production recommendation. For new production applications, use a currently supported Spring Boot release and its supported Java version.

## Safe portfolio practices
- Use synthetic data only. Never commit real customer details, credentials, access tokens, bank data, or production configuration.
- Keep secrets outside source control.
- Add tests as features are introduced.
- Use small commits with clear messages.
